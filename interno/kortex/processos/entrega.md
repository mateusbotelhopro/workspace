# Processo de Entrega — Kortex

## Fluxo padrão

### 1. Setup (Dia 1)
- Criar repositório / ambiente do projeto
- Configurar domínio e hospedagem (se aplicável)
- Definir stack com base no briefing

### 2. Construção
- Executar o projeto com base no escopo aprovado
- Fazer deploys parciais pra cliente acompanhar (link de preview)
- Comunicar progresso por WhatsApp (sem relatório formal)

### 3. Revisão
- Enviar versão final pro cliente revisar
- 1 rodada de ajustes incluída no preço
- Ajustes além da rodada = cobrar hora avulsa

### 4. Entrega
- Deploy em produção
- Transferir acessos pro cliente (domínio, hosting, repo se quiser)
- Enviar documentação básica (como editar, como acessar, o que faz)
- Oferecer manutenção mensal (recorrência)

## Comunicação durante o projeto

- Canal: WhatsApp (direto, sem plataforma de projeto)
- Frequência: update a cada entrega parcial, não diário
- Formato: mensagem curta + link de preview

## Quando o projeto atrasa

- Se atraso é do cliente (demora pra mandar material/feedback): avisar, registrar, não cobrar multa
- Se atraso é da Kortex: comunicar proativamente, dar novo prazo realista
